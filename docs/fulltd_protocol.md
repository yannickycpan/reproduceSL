# Electricity and METR-LA application experiments

**Scope.** This document describes only the two non-FD001 application
campaigns. FD001 is governed solely by
[`dscpuscripts/fd001_protocol.py`](../dscpuscripts/fd001_protocol.py).
There is no legacy FD001 candidate in `fulltd.protocol.make_manifest()`.

The underlying manuscript is *Learning Statistically Efficient TD Operators:
Prediction with Sampled Neighbors and Simultaneous Full Gradients*, v7.
The common data/model/metric utilities remain under `fulltd/`.
Details of architecture/source attribution are in
[`fulltd_architectures.md`](fulltd_architectures.md).

## Methods

For Electricity, TCN runs MSE, TD-full, TD-scalar, Gaussian NLL;
PatchTST runs MSE and TD-full; DLinear runs its ordinary MSE baseline.
For METR-LA, Graph WaveNet runs MSE, TD-full, TD-scalar, Gaussian NLL
and the reference masked-MAE training objective.

All methods use five seeds and 100 training units. Existing non-FD001
training configuration settings and their algorithms are unchanged.
An original TD algorithm uses logical batch 256 and an additional
batch-128 sensitivity configuration. Source/partner sampling, source
masks, weighting, objective gradients and architecture operations are
those implemented by the existing `fulltd` modules. The methods are
evaluated using the same held-out RMSE and MAE measures, regardless
of their training objective.

The non-FD001 manifest now has 510 candidates: 300 Electricity and
210 METR-LA, with the same learning-rate/batch configurations as before.
It is generated by `python -m fulltd.protocol --output configs/fulltd`.
The FD001 protocol has its own 600 candidates and is not part of this
manifest or any mixed Slurm array.

## Optimization, validation, and analysis

Adam uses fixed rates (no schedule, clipping, auxiliary regularization,
or weight decay). In the remaining non-FD001 campaigns, validation is
recorded at rounds 10, 20, ..., 100; each non-FD001 method selects
using mean validation MSE at rounds 80, 90, 100 over five seeds.
Numerical failures invalidate the affected five-seed HP setting.

Electricity samples ceil(N/24) sources independently per round,
and its validation takes reproducible customer-stratified 20% samples.
METR-LA uses full reshuffled training epochs and full fixed validation.
Training source and partner RNG streams remain separate.
Only epoch-end checkpoints are used in these **other-dataset** campaigns.
This epoch-based scheme does not apply to the current FD001 experiment,
which validates and saves every 500 optimizer updates and selects using
the final quarter of positive-update validations.

All test evaluation is separated from HP selection; no method refits
its predictor before held-out evaluation. Dataset processing artifacts,
network initializations, license notices, and evaluation definitions
are maintained in the `fulltd/` source files.
